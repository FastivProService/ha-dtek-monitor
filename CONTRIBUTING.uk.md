# Участь у розробці DTEK Monitor

[English](CONTRIBUTING.md) · **Українська** · [Посібник користувача](README.uk.md)

Повідомлення про помилки, виправлення та покращення документації можна подавати українською або англійською.

## Оберіть репозиторій

Обробка сайту ДТЕК, пошук адрес регіону та сутності HA належать до [DTEK Monitor](https://github.com/groove-max/ha-dtek-monitor). Доставка Telegram, шаблони та визначення живлення за локальними датчиками — до [DTEK Telegram Bot](https://github.com/groove-max/ha-dtek-telegram-bot).

Перед створенням issue перевірте наявні. Додайте версії, кроки відтворення, очікувану/фактичну поведінку й короткий журнал без приватних даних. Не публікуйте токени Telegram/HA, точні приватні адреси або робочі журнали цілком. Для вразливостей є [політика безпеки](SECURITY.uk.md).

## Запуск перевірок

Із кореня репозиторію, після встановлення зазначеної версії Python:

```bash
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -c "import json, subprocess, sys; subprocess.check_call([sys.executable, '-m', 'pip', 'install', *json.load(open('custom_components/dtek_monitor/manifest.json'))['requirements']])"
python -m unittest discover -s tests -v
python -m compileall custom_components tests
```

Без встановленого Home Assistant полегшений набір пропускає тести, що залежать від HA. Для повної перевірки створіть окреме середовище Python 3.14, встановіть `homeassistant==2026.3.0` і залежності manifest та повторіть запуск. Орієнтир — `.github/workflows/tests.yml`; не зараховуйте пропущені тести як успішні.

Зміни постачальника потребують фікстур опублікованих, неопублікованих, порожніх, некоректних і багатогрупових даних. Зберігайте ідентичність оператора/адреси й покриття публікації. Нові регіони додавайте через інтерфейс постачальника та явне ввімкнення, без регіональних умов у сутностях HA.

## Перевірка на працюючій системі

Використовуйте окреме HA/тестове призначення та вимикайте робочу розсилку на час експериментів. Не перемикайте електричне обладнання як побічну дію програмного тесту. Вказуйте, які сценарії перевірені фікстурами, а які спостерігалися наживо.

## Документація та pull request

- Узгоджуйте `README.md` і `README.uk.md`; докладні посібники також мають версії `.uk.md`.
- README має допомагати встановити й використовувати проєкт. Контракти даних і подробиці коду належать до довідника та посібника розробника.
- Перевіряйте відносні посилання та YAML-приклади. Використовуйте умовні адреси й ID сутностей.
- Для зміни поведінки оновлюйте changelog; історичні записи випусків залишаються мовою оригіналу.
- Опишіть проблему, кінцеву поведінку та змістовні перевірки. Зберігайте параметри користувачів та ідентифікатори, якщо немає описаної міграції.
- Не додавайте до Git секрети, приватну діагностику, кеші, віртуальні середовища чи артефакти `graphify-out/`.

Надсилайте власні зміни або код, сумісний із [ліцензією проєкту](LICENSE). Внески подаються під PolyForm Noncommercial 1.0.0 зі збереженням повідомлень про права третіх сторін.

## Перевірка випуску

Запустіть тести HA на `2026.3.0` та `2026.8.3`, як у CI. Окремо встановіть Playwright 1.58.0 і Chromium та запустіть браузерні тести:

```sh
python -m unittest discover -s tests -p 'test_*card.py' -v
```

Теги випусків мають формат `vMAJOR.MINOR.PATCH` з необов’язковим суфіксом `aN`, `bN` або `rcN`. Перевірка: `python scripts/release.py v2.0.0b1`. Версії manifest, кешу JavaScript-модулів і changelog мають збігатися. Суфікси позначають попередній випуск, не замінюючи останню стабільну версію.

Локальна демонстрація — `examples/account-workspace/index.html`. Запустіть `python -m http.server 8974 --bind 127.0.0.1` з кореня репозиторію. Дані вигадані; екрани підключення є макетом і не надсилають SMS або показів.
